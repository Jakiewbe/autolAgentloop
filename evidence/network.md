## 2 方案对比（选一个实际可用的）

| 方案 | 可用性 | 优点 | 代价/风险 | 结论 |

| **Tailscale（WireGuard 私网）** | 未安装，需两端安装 + 各自账号登录（可不同账号，靠共享节点或 tailnet 邀请） | 每个节点拿到固定 100.x 地址、NAT 穿透自动化、断线重连内置、可只放行端口 | 需要两端都能装软件并登录；A 的 TUN 已占用默认路由，需给 tailscale0 加更精确路由（172.16.184.0/24 与 100.64.0.0/10 直连），否则会被代理劫持 | **首选**（目标方案） |

## 3 访问范围设计（A 的中心服务）

任务书要求：A 的任务服务只允许预期私网访问；若绑定所有地址必须有可核对的限制。

设计（写入部署清单，T10 落地时逐条核对）：

1. **中心 HTTP 只绑 loopback 或 tailscale0**：`AGENT_AUTOLOOP_CENTER_HOST=127.0.0.1`（默认），需要 B 跨网时改为 `100.x.y.z`（Tailscale 地址）或 `0.0.0.0` + 防火墙入站规则仅允许 `100.64.0.0/10`。
2. **执行端只出站**：B 主动连 A，A 不主动连 B；这样 A 侧不需要开放任何入站到公网。
3. **两套身份**：管理入口 token（人用，可看/可停）与执行端 token（机器用，只能领任务/回结果）分开，落到不同配置项，互不复用；错误凭据、缺凭据、错类型凭据必须在服务启动后实测被拒（T10/T11 执行，**当前不预先报通过**）。
4. 若用 cpolar 临时隧道，中心不得绑定 `0.0.0.0`；由 cpolar 客户端从 loopback 转发，且额外要求执行端 token + 单次有效连接。
5. 监听范围核对方式：`Get-NetTCPConnection -State Listen | Where LocalPort -eq <port>`，把 `LocalAddress` 记进部署证据。
