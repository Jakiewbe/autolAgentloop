# Agent Loop 可视化面板

本地工作流客户端，连接现有 A 中心。支持回答卡片、结案与请求取消；不修改中台程序、规则或 B 执行端。

启动：`node dashboard/server.mjs`，访问 http://127.0.0.1:3351 。Node 24，无额外依赖。
Windows 后台启动：`powershell -NoProfile -ExecutionPolicy Bypass -File dashboard/start.ps1`；已运行则复用，不重复开启。
首次启动读取当前用户 `.agent-autoloop/config.json` 的 owner，仅供服务端访问中心；密钥不进入网页、URL 或日志。
面板只监听本机回环地址，不接公网隧道。读状态、读单轮 why；写操作仅允许三种固定本人接口，必须是同源 JSON。关闭面板不影响中心或 worker。

## 界面

视觉：深墨色侧栏、温白工作区、少量松绿色强调，信息密集但保持留白。
内容：首页按「等待我决定 / 正在推进 / 接下来」组织；事项工作台、决策中心、任务时间线与后续计划为主；机器连接状态为辅助。
交互：导航切换与抽屉过渡、图表悬停、状态每 5 秒同步；遵守减少动态效果设置。

## 数据口径

- 全局数量与今日用量直接读取中心汇总，不由当前一页任务猜全量数据。
- 事项按中心真实归属 rule + lane 关联：lane 来自该轮 why 事实里 runs 行的权威字段，不是凭 subject、标题、事件文字或会话推断。lane 为空串时只说明这轮的对象标识为空，按规则 + 空对象归组；空 lane 不能反证规则没配过 parallel（parallel 规则下 subject 为空也会有空 lane），面板不据此倒推历史规则。面板为每轮补取 why 只为拿这个字段；取不到时标「未关联的事项」。事项只覆盖已加载的任务。
- 未上报用量/费用显示未上报，不当成 0；失败、取消、未开始、重试分别显示。
- 网络中断保留最后一次成功快照并明确标记过期，不将旧数据称为实时。
- 不展示凭据、卡片授权链接、完整配置或原始环境；任务内容作为纯文字显示。
- 回答不等于后续完成；历史卡片分别显示已回答、后续完成、已关闭。closed 但没有 result 的卡片（fyi 可能是中心创建即 closed）只说「已关闭（仅告知或已结案），没有处理结果记录；面板不补写未发生过的处理」，不替它记一笔没发生的操作。中心重试计数不等于实际模型执行次数。
- 取消是两段式：排队中（queued）中心直接记为已取消；运行中（claimed）只记录取消请求，仍要等执行端确认进程结束，面板写「等待执行端确认停止」。取消被中心记为已取消时只说「中心已确认这轮已取消」——已运行的轮次确认停止后同样是这个状态，面板不从最终状态推断它从未开始。状态待确认（unknown）的轮次中心不接受取消：只说明中心尚未确认结束状态（例如运行中超过租约仍未回报），不猜原因，面板不提供停止入口。提交后立即重新读取，且只有这一次读取本身成功才用它下结论：读取被跳过（已有刷新在跑）或读取失败，都按「没能确认结果、请刷新核对」显示；随后恢复较早历史页的成功读取也不会把未确认改成确认。没有自动重试写操作。
- 后续计划包含已加载的排队 run、规则 next 和 elsewhere；外部计划由外部应用执行。当前状态接口没有统一列出 Agent later 定时器，此页明确不推测全量。
- why 从中心事实读取，展示规则版本、事件、领取、回执和卡片关联；剔除完整配置与密钥表。记录缺失时明确失败，不用摘要拼凑。时间线上只折叠确认为纯保活的心跳（seen/due 行、runs 行状态与会话均未变）；心跳若关闭离线通知、改变轮次状态或切换会话，按真实变化单列。可展开逐条查看，事实本身不删不改序；领取、开始、回答、取消、结束仍单独显著显示。
- 历史分页只用于任务记录页。切到总览、计划或其他视图时一律改用最近一次成功读取的最新快照，并提示「刚才查看的是较早的历史记录页」，不用较早一页推断当前是否有活。
- `/healthz` 报告面板版本与实际写白名单（`writes`），供外部只读核对；`readOnly` 字段已移除，不靠它表示写入能力。

## 验证清单

服务端：真实状态接入；未知字段和授权链接不下发；固定写白名单、同源与输入校验；跨站请求/任意文件读取拒绝；断线明确失败；分页参数校验。
页面：总览数字与中心相同；导航、搜索、状态/执行端筛选、任务详情、历史加载、刷新/暂停可用；费用缺报不伪装为零。
视觉：桌面和窄屏无页面横向溢出；抽屉可关闭和键盘退出；刷新失败时仍能看出数据过期。
探索：搜索零结果、查看取消/失败任务、中心断线模拟、过期快照与重新连接。

测试：`cd dashboard && node --test server.test.mjs app-text.test.mjs`（34 项：rule+lane 分组与空 lane 文案、lane 注入与失败降级、健康检查字段、纯心跳折叠与真实心跳负例、取消文案七分支、跳过/失败读取不得用旧快照确认取消、提交取值顺序、卡片关闭文案与 unknown 租约文案）。只用本地假中心，不派发模型任务。

浏览器验证：`node evidence/dashboard-workflow/fixture-v2.mjs` 在 3353 提供隔离数据（68 轮：>60 已完成 + 1 活动轮 + 历史 parallel 两 lane + 密集心跳 + queued/claimed/unknown 取消 + decided/closed 卡片，假 fetchImpl，不连生产中心），再跑 `node evidence/dashboard-workflow/browser-qa.mjs`（headless Chrome CDP，11 项断言，截图写 `evidence/dashboard-workflow/qa-*.png`）。每次重跑前重启 fixture，因为它按请求在内存里修改状态。
